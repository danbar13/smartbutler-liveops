# SmartButler Digest & SLA Performance Engine

## System Context
This skill automates the ingestion, SLA duration tracking, anomaly detection, and executive morning standup reporting for hotels using **SmartButler by JAYBEE Systems Ltd (jaybee.com)**.

## Input Document Ingestion (Log Report - Providers)
The system must parse SmartButler report exports (PDF, CSV, Excel, or structured text) matching the "Log Report - Providers" schema:
- **Report Metadata**:
  - `report_title`: (e.g., "Log Report - Providers")
  - `site_name`: (e.g., "Grand Hotel")
  - `date_range`: Auto-extracted from "Received Date: DD/Mon/YYYY - DD/Mon/YYYY" (e.g., "01/Sep/2026 - 23/Sep/2026")
- **Row-level Ticket Fields**:
  - `department`: (e.g., Housekeeping, Maintenance, Reception)
  - `description`: Issue title (e.g., "Cleaning - Shower", "AC not working", "Adaptor delivery")
  - `received_at`: Timestamp (e.g., "15/Sep 17:57")
  - `creator`: User who logged the call (e.g., "Roman (1)")
  - `location`: Room or area (e.g., "246", "602", "242")
  - `provided_at`: Completion timestamp
  - `duration`: Actual time taken to resolve in HH:MM (e.g., "191:21", "00:09")
  - `resolver`: Staff member who resolved the ticket
- **SLA & Benchmarking Fields**:
  - `standard`: Target SLA duration threshold in HH:MM (e.g., "00:30", "00:15")
  - `sla_status`: Met (Duration <= Standard) vs. Breached (Duration > Standard or unresolved)
  - `success_rate`: Percentage of calls meeting the standard (`%Success`)

## Data Persistence
- Ingested reports must be saved into a local SQLite/DuckDB database (`./data/smartbutler_history.db`).
- Allows comparative analysis across different uploaded periods and historical lookback.

## UI / Dashboard Architecture (4-Tab Flow)
The application UI must be structured exactly in this sequence:

1. **Tab 1: העלאת דוחות ושמירת נתונים (Upload & Data Ingestion)**
   - Clean upload screen (Drag & Drop for SmartButler PDF/CSV/Excel logs).
   - Shows file parsing status, extracted date range, total parsed tickets, and confirmation of save to history.
   - No dashboards or metrics on this tab.

2. **Tab 2: תדריך להנהלה - ישיבת בוקר (Executive Standup Briefing)**
   - Header prominently displays the parsed operational period (e.g., "תקופת הדוח: 01/09/2026 - 23/09/2026 | מלון Grand Hotel").
   - KPI Cards: סך קריאות (Total Tickets), אחוז עמידה בזמני תקן (% Success Rate), זמן טיפול ממוצע (Avg. Duration), סך שעות טיפול (Total Time).
   - High-level executive bulleted summary highlighting shift performance and major department comparisons.

3. **Tab 3: תובנות עיקריות ומשמעותיות (Key Insights & SLA Bottlenecks)**
   - Deep dive into systemic bottlenecks: Which SLA standards fail most frequently.
   - Analysis of extreme delays (e.g., tasks exceeding SLA by >300%).
   - Staff resolver and creator patterns.
   - Problematic rooms ("חדרים חריגים") with repeated or lingering tickets.

4. **Tab 4: פירוט לפי מודולים ומחלקות (Department Modules & Actionable Breakdown)**
   - Accordion or grouped table view matching SmartButler report hierarchy:
     - Housekeeping (משק בית)
     - Maintenance (אחזקה)
     - Reception (קבלה)
   - Ranked by importance (priority, breach magnitude, and active guest impact).
   - Concrete, departmental action items ("תובנות לפעולה לישיבת הבוקר").
